# Deploying the portfolio (Vercel + Render + Neon)

How the pieces fit together on free tiers:

```
Browser ──► Vercel  ──────────────►  site, /admin and every file in /media
                │
                └── /api/* rewritten ──► Render (Express API) ──► Neon (PostgreSQL)
```

- **Vercel** serves the site *and* all images and documents, so they never depend on the API.
- **Render (free)** runs the API. It sleeps after ~15 minutes without traffic; the next request
  takes 30–60 seconds while it wakes. The site shows skeletons and retries, and images keep
  working because Vercel serves them.
- **Neon (free)** holds the database. Render's own free PostgreSQL expires after 30 days, which
  is why it is not used here.
- The API is reached *through* the site (`/api/…` is rewritten to Render), so the CMS session
  cookie stays first-party — the only setup that works in Safari, which blocks third-party cookies.

Deploy in this order. It takes about 20 minutes.

---

## 1. Database on Neon

1. Sign up at [neon.tech](https://neon.tech) and create a project — region **Singapore** is
   closest to Indonesia.
2. Copy the **pooled** connection string (the host contains `-pooler`). It looks like:
   ```
   postgresql://user:password@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

## 2. API on Render

1. Push this repository to GitHub (it already contains `render.yaml`).
2. In Render: **New → Blueprint**, pick `portofolio-izzul-be`, and Render reads the blueprint.
3. Fill in the variables it asks for:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | The Neon string from step 1 |
   | `CORS_ORIGINS` | Your site URL, e.g. `https://portofolio-izzul-fe.vercel.app` (you can correct this after step 4) |
   | `SITE_URL` | The same URL |
   | `ADMIN_NAME` | `Izzul Faturrizky` |
   | `ADMIN_EMAIL` | The CMS sign-in email |
   | `ADMIN_PASSWORD` | A long password — this creates the first admin account |

   `JWT_ACCESS_SECRET` is generated by Render. Leave the `GITHUB_*` and `SMTP_*` fields empty
   for now (steps 6 and 7).

4. Deploy. The start command runs database migrations first, then boots the API.
5. Check `https://<your-service>.onrender.com/health` — it should answer
   `{"status":"ok","database":"up"}`.
6. Note the service URL. If it is **not** `https://portofolio-izzul-be.onrender.com`, update the
   rewrite in the frontend's `vercel.json` in step 4.

## 3. Load the starting content (once)

Migrations ran on Render, but the content and the admin account come from the seed, which you run
from your machine against Neon:

```powershell
cd portfolio-backend
$env:DATABASE_URL = "postgresql://…neon…/neondb?sslmode=require"
npm run db:migrate      # no-op if Render already migrated
npm run db:seed
Remove-Item Env:DATABASE_URL
```

The seed creates the admin from `ADMIN_EMAIL` / `ADMIN_PASSWORD` in your **local** `.env`, so set
those to what you want before running it (they do not have to match Render's — those are only used
if the account does not exist yet). The password of an existing account is never overwritten; to
change it later use the CMS **Account** page or:

```powershell
npm run admin:password -- you@example.com "a new long password"
```

## 4. Site on Vercel

1. In `portfolio-frontend/vercel.json`, check the rewrite destination matches your Render URL:
   ```json
   { "source": "/api/:path*", "destination": "https://portofolio-izzul-be.onrender.com/api/:path*" }
   ```
   Commit and push if you changed it.
2. In Vercel: **Add New → Project**, import `portofolio-izzul-fe`.
   Framework preset **Vite**, build command `npm run build`, output directory `dist` — all detected
   automatically. Node.js version: **22.x**.
3. No environment variables are needed: `VITE_API_URL` defaults to `/api/v1`, which the rewrite
   sends to Render.
4. Deploy, then note the site URL.

## 5. Point them at each other

1. On Render, set `CORS_ORIGINS` and `SITE_URL` to the real site URL (add a custom domain later as
   a second, comma-separated origin: `https://a.vercel.app,https://izzul.dev`). Save — Render
   redeploys.
2. Open the site. The home page should show the content from the seed.
3. Open `/admin`, sign in, and change the password on the **Account** page.

> The first request after the API has slept takes up to a minute. If the page shows
> "The portfolio could not load", press **Try again** once the API is awake.

## 6. Optional — uploads from the production CMS

Images live in the frontend repository, so the API needs permission to commit there. Without this,
the CMS can still pick existing files; you just add new ones with git.

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens →
   Generate new token**.
   - Repository access: only `portofolio-izzul-fe`
   - Permissions: **Contents → Read and write**
2. On Render, set:

   | Variable | Value |
   | --- | --- |
   | `GITHUB_TOKEN` | The token |
   | `GITHUB_REPO` | `Izzulfr/portofolio-izzul-fe` |

   (`GITHUB_BRANCH=main` and `GITHUB_MEDIA_PATH=public/media` are already in the blueprint.)
3. Redeploy. The CMS **Media** page now says "Committed to GitHub", and every upload becomes a
   commit that Vercel deploys — live in about a minute.

Since uploads are commits, run `git pull` in your local frontend checkout before pushing code.

## 7. Optional — email alert for new contact messages

Messages always land in the CMS inbox. To also get an email, set `SMTP_HOST`, `SMTP_PORT`,
`SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` and `CONTACT_NOTIFY_EMAIL` on Render. With Gmail, use an
[app password](https://support.google.com/accounts/answer/185833), host `smtp.gmail.com`, port 587.

## Custom domain

1. Add the domain in Vercel (**Settings → Domains**) and follow its DNS instructions.
2. On Render, add it to `CORS_ORIGINS` and set `SITE_URL` to it.

Nothing changes on the API side: the browser still talks only to your domain.

## Environment variables on Render, at a glance

| Variable | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | Neon pooled connection string |
| `JWT_ACCESS_SECRET` | yes | Generated by the blueprint |
| `CORS_ORIGINS` | yes | Comma-separated site origins |
| `SITE_URL` | recommended | Used in notification emails |
| `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | first deploy | Only used while seeding |
| `NODE_ENV`, `TRUST_PROXY`, `COOKIE_SAMESITE`, `MEDIA_DRIVER` | preset | From `render.yaml`. `TRUST_PROXY=2` counts both proxies (Vercel, then Render) so rate limits see the visitor's IP; use `1` if the API is called directly instead of through the rewrite. |
| `GITHUB_TOKEN`, `GITHUB_REPO` | optional | CMS uploads (step 6) |
| `SMTP_*`, `MAIL_FROM`, `CONTACT_NOTIFY_EMAIL` | optional | Contact alerts (step 7) |

## When something is wrong

| Symptom | Cause and fix |
| --- | --- |
| Site loads, content shows "could not load" | API asleep (wait and retry) or `CORS_ORIGINS` does not match the site URL exactly, including `https://` and no trailing slash. |
| `/api/...` returns Vercel's 404 page | The rewrite destination in `vercel.json` is not your Render URL. |
| Signed out immediately after signing in | The browser refused the cookie. Keep `VITE_API_URL` unset so the API is proxied, or set `COOKIE_SAMESITE=none` **and** `COOKIE_SECURE=true` on Render. |
| Every `/api/...` route answers 500 `INTERNAL_ERROR` while `/health` says `database: up` | The database connects but has no tables: migrations never ran. Set the Render start command to `npm run db:migrate:prod && npm start` and redeploy, or apply them once from your machine with `DATABASE_URL` pointing at Neon. An empty but migrated database answers 503 `NOT_SEEDED` instead. |
| Browser console shows a CORS error | The site is calling the API cross-origin. Delete `VITE_API_URL` in the Vercel project so the bundle uses `/api/v1` and goes through the rewrite, then redeploy. `CORS_ORIGINS` on Render must list the site origin either way — sign-in checks the `Origin` header even through the proxy. |
| `relation "projects" does not exist` | Migrations did not run. Check the Render start command is `npm run db:migrate:prod && npm start`. |
| Images 404 on the site | The file is not committed in `portfolio-frontend/public/media`. Pull, commit and push. |
| CMS says "Read-only" | No `GITHUB_TOKEN` on Render — expected until step 6. |
| Render build fails on `tsc` | The build must be `npm ci && npm run build`; `npm ci` installs the dev dependencies TypeScript needs. |

## Updating later

- **Content** (text): edit in `/admin` — no deploy needed.
- **Images**: upload in `/admin` (step 6 configured) or commit them to the frontend repo.
- **Code**: push to `main`. Vercel and Render both redeploy automatically; migrations run on boot.
